# Git Guidelines

## Sacred Rule

- **NEVER** run `git push`, `git merge`, `git rebase`, `git commit --amend`, `git reset --hard`, or force-push without explicit user authorization.
- Committing after a task is pre-approved ONLY when invoked via `/orchestrator`, `/handle-ticket`, or `/dev-cycle`, or when the user explicitly asks to commit.
- Run `npm run typecheck` and `npm test` before committing. Run `npm run test:e2e` when the change touches a user-facing flow.
- **Never** claim a check passed that was not actually run. If a check is skipped, say so in the report.

## Branching

- Default branch: **`main`**.
- Feature / fix branches: `feature/<slug>`, `fix/<slug>`, `chore/<slug>`.

## Commit Messages

This repository does **not** use Conventional Commits. Match the existing history instead:

```
git log --oneline
1102a71 Remove screenshot icon artifacts from pickup and drop-off addresses
1c05646 Implement local Uber ride tracker MVP and screenshot review fixes
dbf15ae Initial commit
```

Format:

- One **plain declarative sentence**, sentence case, capital first letter, **no trailing period**.
- **No type prefix** (`feat:`, `fix:`, `chore:` are all absent from this history — do not introduce them).
- **No commit body, no trailers, no `Co-Authored-By`, no `Fixes #` footer.**
- 47–74 characters. One commit per delivered unit of behaviour, not one per file — substantial work gets one sentence summarizing the whole change set.
- When a change traces to acceptance criterion `A<nn>` or milestone `M<n>`, append it as a parenthetical: `Reject blank amounts as unknown rather than zero (A04)`.

Examples:
```
Replace blank amount inputs with explicit unknown state (A04)
Add restore preview and activate with retained prior generation (A18)
Strip pin glyphs from OCR pickup and drop-off addresses
Reject foreign origin and cross-site requests at the API boundary (A20)
```

## Workflow

1. `git status` — check what actually changed before staging anything.
2. Stage **explicit paths only**: `git add <path1> <path2>`.
3. **Never** `git add -A`, `git add .`, or `git add -u`.
4. Verify the staged set with `git status` and `git diff --cached --stat`. If it contains a file you were not asked to change, unstage it and stop.
5. Commit.
6. Report the hash, the subject, and the file list from `git show --stat --oneline HEAD`.

## .gitignore Discipline

Never commit:
- `node_modules/`, `dist/`, build output
- `.DS_Store`
- `*.sqlite*` — this covers the database **and** its `-wal` / `-shm` sidecars
- `playwright-report/`, `test-results/`
- `public/ocr/` — generated by `npm run setup:ocr`, contains ~38 MB of Tesseract binaries
- `.env*`

Also gitignore `.context/` — it is agent pipeline state (cycle state, findings, caches), not source. It is regenerable and does not belong in history.

Runtime data lives outside the repo entirely: `~/Library/Application Support/Uber Ride Tracker`, overridable with `UBER_DATA_DIR`.
